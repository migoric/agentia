# 决策锚点：从「日期 + 圈号」迁到「日期 + slug」

- 日期：2026-10-14
- 状态：**P1 已定稿并实施中**（2026-10-14）—— §7 的开放问题已在 §7.1 逐条回答，形态见 §7.2；P2/P3 未开工
- 起因：`docs/reviews/2026-10-13/` 的收口审计（22 行 / 23 处错引，见 `CHANGELOG.md` 的「引用完整性轮」）
- 相关守卫：`tests/docs/circle-refs.test.ts`（现役）、`tests/architecture/duplicated-blocks.test.ts`

## 1. 问题：编号是**位置号**，而位置会变

`docs/spec.md` §10 给每条决策一个锚点，全仓用 `（日期 圈号）` 指回去。这在一份**只增不改**的
日志上本该很稳，但实测的 23 处错引里，**14 行是同一种成因**：

> 同一个 PR 自己的分支已经把那四件事编成 ⑨⑩⑪⑫，**同一分支**的 `tests/**` 与 `AGENTS.md`
> 仍写 ①②③④ —— 偏差恒为 +8。**落地当天就自相矛盾**，与合并无关。

⇒ 编号是**按天**编的**位置号**：同一天里插一条、重排一次，这条决策的地址就变了，而引用它的
地方**一个都不会红**。这是结构性的，不是注意力问题 —— 写引用的那天它是对的。

同一成因的第二个观测：`CHANGELOG.md` 里引该日 ⑲ 的那条标题，而 ⑲ **在 §10 从未存在过**
（正对照验过：`git log -S` 搜同日的 ⑳ 能命中，搜 ⑲ 为空）—— 作者当时"按圈号"在写，但那天
根本没有这个号。**位置号允许「有一个号但没人知道它指什么」这种状态存在。**

## 2. 目标与非目标

**目标**：让每条决策有一个**稳定的名字**，使得

1. 引用写下去之后**不会因为别处插入一条而失准**；
2. 「查不到」与「查到别的」可区分 —— 前者能被机器咬住，后者才需要人读；

**非目标**（明确不做，免得这一轮被读成「顺手整理」）：

- **不拆 `docs/spec.md`**（会撞死引用，本轮修的正是这类撞伤）；
- **不给同日编号补号**（`guards.md` §1.4 已登记：补号本身会撞死引用，收益抵不过风险）；
- **不改历史**：`docs/plans/**` 与 `docs/reviews/**` 是带日期的快照，里面的圈号引用**不动**。

## 3. 方案：锚点带 slug，slug 由**标题**派生

锚点形态从「**日期 + 位置号**」变成「**日期 + 名字**」：

```
  现在：  ### <日期> ⑨：<标题>              # ⑨ = 同一天里的第 9 条 —— 中间插一条就移位
  改为：  ### <日期> ref-integrity：<标题>   # 名字不随「别处插入」而变化
```

引用从 `（<日期> ⑨）` 变成 `（<日期> ref-integrity）`。

> ⚠️ 本文件这里的例子**刻意用占位符**（`<日期>` / `<标题>`），不写任何一个真实的
> 「日期 + 圈号」字面量 —— 因为那正是本设计要消灭的形状：写下一个真实的号，就等于在这份
> 文档里埋一个「将来会失准」的引用（`tests/docs/circle-refs.test.ts` 只判号在不在，判不了
> 指得对不对）。**论证「位置号会腐烂」的文档，自己不该先写一个位置号。**

### 3.1 slug 的三条硬要求

| 要求 | 为什么 |
|---|---|
| **稳定** | 它不许随「同一天插了一条」而变化 ⇒ 这正是要买的东西 |
| **唯一** | 同一天内不许重名（跨天可以重 —— 前缀有日期） |
| **可机械校验** | 锚点写出的 slug 与引用写的 slug 必须能**字符串相等**对拍（这就是守卫的全部机制） |

### 3.2 slug 从哪来（**推荐：显式声明优先，标题派生兜底**）

- **首选**：锚点行里**显式写出** slug，位置在「日期 + 圈号」之后（P1 定稿形态见 §7.2）：
  `### <日期> <圈号> ref-<名>：<中文标题>`。
  ⚠️ 示例**必须写成占位符**：写成「具体日期 + 具体 slug」就成了 `（日期 slug）` 形态的**真引用**，
  而它指向的 slug 并不存在于 §10 ⇒ 会被 `circle-refs` 判成「查不到」咬红（**实测踩过这一次**）。
  理由：派生规则再聪明也会在中文标题上失手（本仓标题几乎全是中文，ASCII 片段常常为 0），
  而**失手的派生 = 一条静默错锚点**，正好是这一轮要消灭的东西。
- **兜底**：标题里已有 ASCII 标识符（如 `transplant-copy`、`schema-cache`）时，允许省略显式
  slug ⇒ 解析器取**标题里第一个 ASCII 标识符块**当 slug。⚠️ 这条兜底**必须**配一条
  「省略时派生的 slug 在全仓唯一」的断言，否则两个标题里都含 `cache` 就撞了。

> ⚠️ 未定项（P1 定稿已答，见 §7.1）：兜底派生要不要**允许**？本文件倾向「**不允许省略**」——
> 显式声明比聪明派生更符合本仓「能机械判的才写进守卫」的一贯做法。**定稿结论：不留兜底**。

### 3.3 迁移分三步，每步都能独立验证

| 阶段 | 动作 | 做完这一阶段，守卫能咬住什么 |
|---|---|---|
| **P1 加名** | 给 §10 每条锚点补 slug；**引用一个都不动**；守卫放宽成「圈号 **或** slug 解析得到即可」，并新增「slug 唯一」与「解析数下限」 | 新写的引用若用 slug，写错当场红；老引用仍在 |
| **P2 换引用** | 脚本批量把射程内的 `（日期 圈号）` 换成 `（日期 slug）`；按**文件**分批提交（便于 review 与回滚） | 混用期：守卫要求两者都能解析 |
| **P3 收口** | 守卫只认 slug；同日的「圈号」降级为**显示用编号**（可以继续在标题里出现，但**不再是地址**） | 任何人再写 `（日期 圈号）` 直接红 |

**P1 是本设计的全部价值所在，也是最便宜的一步** —— 它不改任何一条既有引用，只给锚点加名。

### 3.4 放宽期不许变成放松

P1/P2 期间守卫接受两种形态。**这是一次有期限的放宽**，写法上要立三条：

1. 放宽的代码里必须写明**退出条件**（P3 删掉这一支）与**当前阶段**；
2. 放宽期必须**收紧另一头**：`slug` 与 `圈号` 在**同一个锚点上必须同时存在**（即不允许
   「只有 slug、但同日的圈号丢了」）—— 否则 P3 收口时会发现锚点对不齐，而那时引用已经全改了；
3. 放宽的分支要有**自证**：断言「当前仓库里 slug 锚点数 ≥ N」，否则解析器退化成 0 也没人知道。

## 5. 回滚

- 无外部状态：P1/P2 全是仓库内的文本改动 ⇒ `git revert` 即回滚；
- P1 与 P2 **分开提交**，所以「加了名但不想换引用」是可停下来的状态；
- 真有问题的批次可以单独 revert，不影响其它批次（这正是分批的理由）。

## 6. 验收判据（都可机械判）

1. **P1 完成**：射程内 `（日期 slug）` 能解析到的引用数 ≥ 1（证明新形态真的通了）；
   且 §10 的 slug 锚点数 == 圈号锚点数（119），**且 slug 互不重复**；
2. **P3 完成**：扫描射程，`（日期 圈号）` 命中数 == 0；
3. **变异验证**（P1 与 P3 各做一次，逐条记录红在哪一条）：
   - 把某条锚点的 slug 改名 ⇒ **恰好**引用它的那些行红；
   - 造一个重名 slug ⇒ 唯一性那条红；
   - 把解析正则打瞎 ⇒ 真空护栏红（**不是**「全绿」）；
4. **不许出现**：`slug` 派生失败却静默跳过（那就是「查不到」与「查到别的」不可区分的状态）。

## 7. 开放问题（P1 定稿前必须回答，别默认）

1. **兜底派生要不要留**（§3.2）？—— 倾向不留，代价是每条锚点都要人手写一个 slug；
2. **slug 的字符集**：只许 `[a-z0-9-]`？要不要允许下划线、数字开头？（数字开头会让
   「`2026-10-14 2fa`」在解析时与圈号混淆的可能 —— 需要一次负向对照实验）
3. **同日多条的 slug 前缀**要不要统一加日期（像本文件的 `ref-integrity` 那样）？本文件倾向
   **不加**：日期已经在锚点前缀里，slug 自带日期等于把同一个事实写两遍；
4. `AGENTS.md` / `CONTRIBUTING.md` 里有没有必要教「怎么写这个引用」？—— 若 P3 之后引用不再是
   位置号，那这件事就该写进那两份必读文档的一段，否则新人只能照着旧例子抄。
5. **P3 判据的口径**（P1 实施时发现，未答）：§6.2 写「扫描射程，`（日期 圈号）` 命中数 == 0」，
   但**守卫与探针都把 §10 的锚点定义行也按该形态计入**（`### 日期 ②` 本身就是「日期 + 圈号」）；
   P3 之后圈号按设计仍留在锚点行上（退化成**显示编号**）⇒ 这个 **0 永远达不到**。P3 收口时判据
   要么改成「**非定义行**的命中数 == 0」，要么给 `isDefLine` 一个排除口。
   **P1 实测**：射程内（跟踪口径 483 处）里有 **121 处**正是定义行自身。

## 7.1 定稿结论（2026-10-14，P1 实施时补）

四个开放问题逐条回答，并修正两处与实测不符的判据。

| # | 问题 | 结论 |
|---|---|---|
| 1 | 兜底派生留不留（§3.2） | **不留**。本仓标题几乎全中文、ASCII 片段常为 0；「派生失手」产出的是一条**静默错锚点**，正是本设计要消灭的东西。每条锚点人手写，代价一次性付清 |
| 2 | slug 字符集 | `^ref-[a-z0-9]+(-[a-z0-9]+)*$`，总长 ≤ 48。**强制 `ref-` 前缀** ⇒ 「数字开头」构造不出来（`ref-2fa` 以 `r` 起头），§7 里担心的「与圈号解析混淆」**不成立**，那个负向实验不必做 |
| 3 | 同日多条要不要加日期前缀 | **不加**。日期已经在锚点前缀里，加上等于把同一事实写两遍 |
| 4 | `AGENTS.md`/`CONTRIBUTING.md` 要不要教怎么写 | **P1 不教，P3 才教**。P1 期两种写法并存、引用一处未动 ⇒ 此时教谁都是半对。P1 只在 `docs/spec.md` §10 章节头加一段读者指引（说明每行为何多一个英文名） |

**实测修正两处**（设计时未量到）：

1. **射程是 120 行，不是 119 个**。§10 里带圈号的锚点**定义行**共 **120 行**，其中 `2026-09-14 ②`
   出现**两次**（同日重号，守卫用 Map 先到先得 ⇒ 唯一键 119）。判据因此改成：
   **120 行每行都有 slug，且 120 个 slug 互不相同**。`slug 数(120) > 圈号唯一键数(119)` 是**有意为之** ——
   圈号区分不了那两行，slug 能，这恰是「位置号换名字」收益的一个具体证据。
   ⚠️ 已查：`（2026-09-14 ②）` 在射程内的引用数 = **0** ⇒ 该重号**不产生 P2 换引用的歧义**。
2. **无圈号的锚点不在 P1 射程**。§10 另有 4 条 `### 日期：…`（同日首条无编号，守卫头注「定点不咬」第 2 类）
   与 45 条 `- 日期：…` 条目行。它们本就不产生圈号锚点、也无人引用 ⇒ P1 不动
   ⇒ §6.1 里「slug 锚点数 == 圈号锚点数」据此改成上面第 1 条的口径。

> **落地后复算（2026-10-14，同日）**：上面第 1 条的读数是 **P1 落地那一刻**的；随后 `docs/spec.md` §10
> 又加了 P1 自己那条决策（它同样带圈号 + slug）⇒ 现为**定义行 121 / 圈号唯一键 120 / slug 121**。
> 两处口径的**关系**不变（slug 数比圈号唯一键多 1 —— 同日重号那一行仍靠 slug 区分），P2 的射程
> （全仓 508 处引用）也不受影响。⚠️ 守卫的真空下界**刻意不跟着抬**（写成 119 的**量级**值，见守卫
> 注释）—— 「钉死当前值」的断言会随文档增长而悄悄失效，而失效时没有任何东西会响。

### 7.2 形态（P1 定稿）

slug 插在**「日期 + 圈号」之后**，其余原样：

```
### 2026-09-14 ② ref-hard-timeout：`withTimeout` 收紧为**硬保证**
### 2026-09-14 ② ref-expand-closeout「展开」收尾：版式回摆 + …
**2026-09-17 ⑤ ref-cross-process-links —— trace 跨进程关联：…**
```

选这个位置（而非 §3.2 字面说的「日期之后」）的理由：**既有 `ANCHOR` 正则要求「日期后紧跟圈号」，
这样它一个字都不用改** ⇒ P1 只新增一支 slug 解析，不动既有解析 —— 正符合 §3.3 说的「P1 是最便宜的一步」。

## 7.3 P2/P3 定稿口径（2026-10-14，P2 实施时补）

§7 第 5 条（P3 判据的口径）是本轮**唯一必须现答**的问题，因为 P2 与 P3 共用一个射程 ——
口径不说清，替换与判据会各按各的理解走。

**射程方程（P2 与 P3 共用，三项都是减法，每项都有出处）**：

```
P2/P3 射程 = 守卫射程                                （见守卫头注「一条规则，两档射程」）
           − docs/plans/** 与 docs/reviews/**        （设计稿 §2：带日期的快照，圈号引用不动）
           − §10 的锚点定义行自身                     （圈号按设计**保留**为显示编号）
           − 日期在 §10 没有条目的引用                （守卫既有闸：该号指别的文档自己的编号）
```

**实测（2026-10-14，`main` 的 `88d4c5f`）**：射程内共 **483** 处可解析引用 =
**121** 定义行 + **57** 快照 + **302** 待替换；另 3 处的日期（`2026-10-11`）在 §10 没有条目 ⇒ 不动。

| 结论 | 内容 | 为什么 |
|---|---|---|
| **P2 射程** | **302 处 / 84 个文件** | 上表减法；射程内**每一处**圈号都能映射到该日 §10 的 slug（实测失败 0 处） |
| **P3 判据** | 射程内**非定义行、非快照、日期有条目**的「日期 + 圈号」引用数 **== 0** | §6.2 原文的「命中数 == 0」永远达不到 —— 定义行自身就是该形态（121 处），且快照刻意保留（57 处）。**把这两类写进判据的减法里，比给 `isDefLine` 加排除口更清楚** |
| **多圈号形态** | `（日期 ②③）` → `（日期 ref-a ref-b）`（空格分隔） | 与圈号支对称 —— 原来就吃「一整串圈号」。⚠️ **守卫的 slug 支必须同时改成逐个校验**（守卫头注早写过这条要求：「别只放宽正则」）。本仓实测 5 行 / 10 处 |
| **快照里不被校验** | P3 后 `REF` 只认 slug ⇒ plans/reviews 里的圈号**天然不被匹配**、也就不会被咬 | 与 §2 非目标一致。但**这个「不咬」是刻意的**，故 P3 的残留计数要显式排除它们，而不是靠「没匹配到」 |

**P3 判据为什么要写成「减法」而不是「改 `isDefLine`」**：判据要能被人一眼复核。
「射程 − 快照 − 定义行」三项各自是一条**已写在别处的规则**（§2、§3.3、守卫头注），
读判据的人顺着三项去查即可；而 `isDefLine` 这种排除口是**判据内部的实现细节**，
读的人看不到它把什么排除了 —— 那正是「守卫声称的理由没人守」的温床。

## 8. 与既有决策的关系
