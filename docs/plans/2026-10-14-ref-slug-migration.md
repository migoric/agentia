# 决策锚点：从「日期 + 圈号」迁到「日期 + slug」

- 日期：2026-10-14
- 状态：**设计稿（P1 未开工）** —— 本文件只冻结方案与验收判据，落地代码留到下一轮
- 起因：`docs/reviews/2026-10-13/` 的收口审计（22 行 / 23 处错引，见 `CHANGELOG.md` 的「引用完整性轮」）
- 相关守卫：`tests/docs/circle-refs.test.ts`（现役）、`tests/architecture/duplicated-blocks.test.ts`

## 1. 问题：编号是**位置号**，而位置会变

`docs/spec.md` §10 给每条决策一个锚点，全仓用 `（日期 圈号）` 指回去。这在一份**只增不改**的
日志上本该很稳，但实测的 23 处错引里，**14 行是同一种成因**：

> 同一个 PR 自己的分支已经把那四件事编成 ⑨⑩⑪⑫，**同一分支**的 `tests/**` 与 `AGENTS.md`
> 仍写 ①②③④ —— 偏差恒为 +8。**落地当天就自相矛盾**，与合并无关。

⇒ 编号是**按天**编的**位置号**：同一天里插一条、重排一次，这条决策的地址就变了，而引用它的
地方**一个都不会红**。这是结构性的，不是注意力问题 —— 写引用的那天它是对的。

同一成因的第二个观测：`CHANGELOG.md` 里引该日 ⑲ 的那条标题，而 ⑲ **在 §10 从未存在过**
（正对照验过：`git log -S` 搜同日的 ⑳ 能命中，搜 ⑲ 为空）—— 作者当时"按圈号"在写，但那天
根本没有这个号。**位置号允许「有一个号但没人知道它指什么」这种状态存在。**

## 2. 目标与非目标

**目标**：让每条决策有一个**稳定的名字**，使得

1. 引用写下去之后**不会因为别处插入一条而失准**；
2. 「查不到」与「查到别的」可区分 —— 前者能被机器咬住，后者才需要人读；

**非目标**（明确不做，免得这一轮被读成「顺手整理」）：

- **不拆 `docs/spec.md`**（会撞死引用，本轮修的正是这类撞伤）；
- **不给同日编号补号**（`guards.md` §1.4 已登记：补号本身会撞死引用，收益抵不过风险）；
- **不改历史**：`docs/plans/**` 与 `docs/reviews/**` 是带日期的快照，里面的圈号引用**不动**。

## 3. 方案：锚点带 slug，slug 由**标题**派生

锚点形态从「**日期 + 位置号**」变成「**日期 + 名字**」：

```
  现在：  ### <日期> ⑨：<标题>              # ⑨ = 同一天里的第 9 条 —— 中间插一条就移位
  改为：  ### <日期> ref-integrity：<标题>   # 名字不随「别处插入」而变化
```

引用从 `（<日期> ⑨）` 变成 `（<日期> ref-integrity）`。

> ⚠️ 本文件这里的例子**刻意用占位符**（`<日期>` / `<标题>`），不写任何一个真实的
> 「日期 + 圈号」字面量 —— 因为那正是本设计要消灭的形状：写下一个真实的号，就等于在这份
> 文档里埋一个「将来会失准」的引用（`tests/docs/circle-refs.test.ts` 只判号在不在，判不了
> 指得对不对）。**论证「位置号会腐烂」的文档，自己不该先写一个位置号。**

### 3.1 slug 的三条硬要求

| 要求 | 为什么 |
|---|---|
| **稳定** | 它不许随「同一天插了一条」而变化 ⇒ 这正是要买的东西 |
| **唯一** | 同一天内不许重名（跨天可以重 —— 前缀有日期） |
| **可机械校验** | 锚点写出的 slug 与引用写的 slug 必须能**字符串相等**对拍（这就是守卫的全部机制） |

### 3.2 slug 从哪来（**推荐：显式声明优先，标题派生兜底**）

- **首选**：锚点行里**显式写出** slug，位置固定在日期之后：
  `### 2026-10-14 ref-integrity：<中文标题>`。
  理由：派生规则再聪明也会在中文标题上失手（本仓标题几乎全是中文，ASCII 片段常常为 0），
  而**失手的派生 = 一条静默错锚点**，正好是这一轮要消灭的东西。
- **兜底**：标题里已有 ASCII 标识符（如 `transplant-copy`、`schema-cache`）时，允许省略显式
  slug ⇒ 解析器取**标题里第一个 ASCII 标识符块**当 slug。⚠️ 这条兜底**必须**配一条
  「省略时派生的 slug 在全仓唯一」的断言，否则两个标题里都含 `cache` 就撞了。

> ⚠️ 未定项（留到 P1 设计定稿时答）：兜底派生要不要**允许**？本文件倾向「**不允许省略**」——
> 显式声明比聪明派生更符合本仓「能机械判的才写进守卫」的一贯做法。见 §7。

### 3.3 迁移分三步，每步都能独立验证

| 阶段 | 动作 | 做完这一阶段，守卫能咬住什么 |
|---|---|---|
| **P1 加名** | 给 §10 每条锚点补 slug；**引用一个都不动**；守卫放宽成「圈号 **或** slug 解析得到即可」，并新增「slug 唯一」与「解析数下限」 | 新写的引用若用 slug，写错当场红；老引用仍在 |
| **P2 换引用** | 脚本批量把射程内的 `（日期 圈号）` 换成 `（日期 slug）`；按**文件**分批提交（便于 review 与回滚） | 混用期：守卫要求两者都能解析 |
| **P3 收口** | 守卫只认 slug；同日的「圈号」降级为**显示用编号**（可以继续在标题里出现，但**不再是地址**） | 任何人再写 `（日期 圈号）` 直接红 |

**P1 是本设计的全部价值所在，也是最便宜的一步** —— 它不改任何一条既有引用，只给锚点加名。

### 3.4 放宽期不许变成放松

P1/P2 期间守卫接受两种形态。**这是一次有期限的放宽**，写法上要立三条：

1. 放宽的代码里必须写明**退出条件**（P3 删掉这一支）与**当前阶段**；
2. 放宽期必须**收紧另一头**：`slug` 与 `圈号` 在**同一个锚点上必须同时存在**（即不允许
   「只有 slug、但同日的圈号丢了」）—— 否则 P3 收口时会发现锚点对不齐，而那时引用已经全改了；
3. 放宽的分支要有**自证**：断言「当前仓库里 slug 锚点数 ≥ N」，否则解析器退化成 0 也没人知道。

## 4. 射程与代价（实测，2026-10-14）

| 量 | 读数 | 出处 |
|---|---|---|
| §10 锚点 | 119 个 / 15 个日期段 | `circle-refs.test.ts` 的真空护栏读数 |
| 射程内 `（日期 圈号）` 引用 | 508 处 | 扫描器探针（`.workbuddy/probes/2026-10-14-circle-ref-scan-v4.mjs`，未入库） |
| P2 会改动的行 | 500+ 行、跨约 40 个文件 | 同上 |

⇒ **P2 必须按文件分批，且每批单独跑变异验证**（改 500 处引用而不分批，diff 里看不出哪一处
是手滑）。

## 5. 回滚

- 无外部状态：P1/P2 全是仓库内的文本改动 ⇒ `git revert` 即回滚；
- P1 与 P2 **分开提交**，所以「加了名但不想换引用」是可停下来的状态；
- 真有问题的批次可以单独 revert，不影响其它批次（这正是分批的理由）。

## 6. 验收判据（都可机械判）

1. **P1 完成**：射程内 `（日期 slug）` 能解析到的引用数 ≥ 1（证明新形态真的通了）；
   且 §10 的 slug 锚点数 == 圈号锚点数（119），**且 slug 互不重复**；
2. **P3 完成**：扫描射程，`（日期 圈号）` 命中数 == 0；
3. **变异验证**（P1 与 P3 各做一次，逐条记录红在哪一条）：
   - 把某条锚点的 slug 改名 ⇒ **恰好**引用它的那些行红；
   - 造一个重名 slug ⇒ 唯一性那条红；
   - 把解析正则打瞎 ⇒ 真空护栏红（**不是**「全绿」）；
4. **不许出现**：`slug` 派生失败却静默跳过（那就是「查不到」与「查到别的」不可区分的状态）。

## 7. 开放问题（P1 定稿前必须回答，别默认）

1. **兜底派生要不要留**（§3.2）？—— 倾向不留，代价是每条锚点都要人手写一个 slug；
2. **slug 的字符集**：只许 `[a-z0-9-]`？要不要允许下划线、数字开头？（数字开头会让
   「`2026-10-14 2fa`」在解析时与圈号混淆的可能 —— 需要一次负向对照实验）
3. **同日多条的 slug 前缀**要不要统一加日期（像本文件的 `ref-integrity` 那样）？本文件倾向
   **不加**：日期已经在锚点前缀里，slug 自带日期等于把同一个事实写两遍；
4. `AGENTS.md` / `CONTRIBUTING.md` 里有没有必要教「怎么写这个引用」？—— 若 P3 之后引用不再是
   位置号，那这件事就该写进那两份必读文档的一段，否则新人只能照着旧例子抄。

## 8. 与既有决策的关系

- 本设计**不改** `docs/spec.md` §10 的**规则本身**（每条决策一个锚点、只增不改），只换
  **锚点的名字形态**；
- 「同日编号必须连续」这条更硬的闸**仍然不做**（`guards.md` §1.4 已登记理由）：P3 之后编号
  退化成显示，它的连续性就**不再承重** —— 这是本设计顺带消掉的一个历史包袱；
- 落地时按 `CONTRIBUTING.md` 的判据决定要不要写 `docs/spec.md` §10：**这是语义变更**
  （引用形态是对外约定的一部分，`AGENTS.md` 与 PR 模板里都出现过），故**要写**。
