## 2. 决策一：判据用**行数**，不用**比例**（⚠️ 报告的这条建议被否掉）

**报告原建议**：判据用「最大方法 ÷ 文件总行数」，理由是能抓住「文件几乎等于一个函数」的形状。

**实测后否掉**。这条的证伪过程值得留档，因为它是本稿唯一一条**推翻了输入材料**的判断：

| 步骤 | 读数 |
|---|---|
| `mcp-http.ts:createStreamableHttpMcpConnector` 修前 | **265** 行 / 文件 316 = **84%** |
| 抽走 74 行到 `mcp-protocol.ts` 之后 | **191** 行 / 文件 245 = **78%** |
| ⇒ 比例只降了 **6pt** | 因为**分子分母同减**：抽件在减分子的同时也减分母 |

`mcp-server-http.ts` 同款：`startHttpTransport` 修前 192/220 = **87%**，抽走五个纯件后**体仍有
145 行**（占文件比例降下来了，但**那不是重点** —— 重点是「体本身没变」）。这个数的意义在于：
**比例判据的下限被文件的脚手架行数顶住** —— 一个工厂再拆，只要它自己的骨架还在，比例就下不到
哪里去。要让比例判据「当时就咬」，阈值只能落在 76~79% 这个区间，**离任何诚实阈值 1~4pt** ⇒
相邻一次正常迭代就会误报。`docs/guards.md` §3 第 1 条（宁可窄不要误报）直接禁掉这条路。

⚠️ 本稿**刻意不写「修后百分比」**：头部注释一改分母就变（本稿自己就踩过一次 —— 写完
「145/260 = 56%」之后又去改了两个文件的头注）。行数（体）是稳的，比例不是。

⇒ **采用绝对行数 240**：越线的三个（265 / 257 / 252）与合法那一档的**上界**（224，
`renderPrometheus`）之间只有 28 行；240 落在中间 —— 给合法档 16 行（7%）余量，
同时把三个越线者**全部**点出来。实测的口径：**改动前红、点名恰好三个；改动后绿。**

**代价（写进 `guards.md` 的盲区栏，不藏）**：`startHttpTransport` 占文件 87%（当天全仓最高
比例）而**体 145 行不过线 ⇒ 本闸不管它**。它是「文件基本等于一个函数的壳」，只有比例判据
看得见 —— 而比例判据被否掉了。这条**已知盲区**是本次决策的显式代价。

## 3. 决策二：闸怎么落地（三层，各自独立可验）

| 层 | 文件 | 为什么这样切 |
|---|---|---|
| 扫描器 | `tests/architecture/lib/callable-spans.ts` | 它**自己要能被单独验证**。失效方向是**假阴性**（识别不出体 ⇒ 表是空的 ⇒ 闸全绿），而那与「体量健康」看起来一样。写在 `.test.ts` 里做不到 —— import 测试文件会直接跑测试（同 `lib/source-scan.ts` 的理由） |
| 守卫 | `tests/architecture/method-size.test.ts` | 一条**真空护栏**（文件数 / 体个数 / 大文件数三条下限 + 「`mcp-http.ts` 必须在射程里」）+ 五条**扫描器自证**（钉精确行数，不写「差不多」）+ 一条棘轮 |
| 登记 | `docs/guards.md` §1.1 | 元守卫要求；「退化了会怎样」栏里写明**两条已知偏离**（比例盲区 + `foo({` 假阳性） |

口径三条**刻意**与兄弟闸不同，都写进了头注：① 量**原始行**（含空行与体内注释），
`source-size` 量「含代码行」；② 按**体**不按文件；③ 判据是行数不是比例。

## 4. 决策三：外移的边界（搬什么、不搬什么）

三条外移的**共同判据**：**这段代码能不能被局部问答？** 能 ⇒ 搬；不能（要读状态机）⇒ 留。

| # | 搬走的东西 | 从 | 到 | 搬后 |
|---|---|---|---|---|
| 1 | 两个连接器**各自抄了一份**的协议面：JSON-RPC 结果提取 / HTTP 错误包装 / `tools` 清单校验 / `isError` 拒绝 / 会话自愈判定（**7 个**） | `mcp-http.ts` + `mcp-stdio.ts` | `mcp-protocol.ts`（已存在的共享面） | `mcp-http` 工厂 **265 → 191** |
| 2 | 子进程退出观察面 + 收尾（`trackChildExit` / `reapChild`）与 stdout 分帧派发（`dispatchLine`） | `mcp-stdio.ts` 的 `ensureProc` / `close` | 同文件模块级 | 工厂 **252 → 213**（文件反而 +24 —— 见 §6） |
| 3 | **逐字**外移 HTTP 宿主的五个纯件（`sendJson` / `readBody` / `jsonRpcIdOf` / `startListening` / `closeOwnServer`） | `mcp-server-http.ts` 的 `startHttpTransport` | 同文件模块级 | **192 → 145** |
| 4 | 42 行 run 选项装配 + 幂等去重的终态采纳 | `async.ts` 的 `#executeInner` | **新文件** `transport/run-call-options.ts` | `#executeInner` **257 → 217**（文件 1460 → 1419） |

`mcp-stdio.ts`（stdout 分帧解析是传输特有的），`ASSIGN_OBJECT` 那条判据留下但**如实标注

## 5. 射程与已知偏离（不藏）

1. **比例盲区**：见 §2 末。`startHttpTransport` **修前** 87% 而体不过线 ⇒ 本闸不管它。
2. **唯一的误咬方向**：多行**调用**传对象字面量实参（`foo({`）签名里带 `(` ⇒ 被判成一个体。
   全量实测：538 个体里 **4 个**、最大 **9 行**（`metrics-otlp.ts` / `loop-result.ts` /
   `usage.ts` / `loop.ts`）⇒ **今天不产生误报**。这是唯一能让守卫误咬的方向，已写进头注。
3. **文本扫描器不是 AST**：已知偏离四类（一行多体 / 无花括号箭头 / 被遮蔽之外的 `{` /
   `foo({`）。前三类在本仓语料里不存在，方向都是**读数偏小**。
4. **`ASSIGN_OBJECT` 不承重**：被第 4 条判据包含 ⇒ **单独删它不会有任何用例红**。按
   §3 第 2 条的要求**如实说明**，不假装它有一条自己的变异。

## 6. 一个反直觉的读数（必须写明，否则下一个人会以为搬错了）

**外移让总行数上升。** 七个文件：base 合计 **2569** 行 → 现在 **2801** 行（**+232**）。

| 文件 | base | 现在 |
|---|---:|---:|
| `integrations/mcp-http.ts` | 316 | 245 |
| `integrations/mcp-stdio.ts` | 311 | **335** |
| `integrations/mcp-protocol.ts` | 158 | **294** |
| `transport/async.ts` | 1460 | 1419 |
| `transport/run-call-options.ts` | — | 128 |
| `engine/mcp-server-http.ts` | 220 | **262** |
| `engine/mcp-server-stdio.ts` | 104 | 118 |

原因不是「多写了代码」，是**注释是证据载体**：搬走的每一块都带着它自己的「为什么外移」，
而本仓注释占 29~55%。这个方向**没有守卫会被触发**（`source-size` 是**单文件** 750 的闸，
没有全仓总量闸；`packages/cli` 的 `TOTAL_BUDGET` 只管 CLI 自己）。
⇒ 记在这里，免得下次有人看到「抽件之后总行数变大」以为搞错了。

## 8. 本轮**踩到并修掉**的两个坑（都是「守卫自己骗人」那一类）

1. **第一版自证样本 ③ 是假守卫。** 它把花括号放在**单独一行**里，而 `after === before + 1`
   这个判据**对整体深度平移是免疫的** ⇒ **摘掉遮蔽照样绿**。真实病灶的形状是「花括号与体的
   开括号**同一行**」（那里遮蔽与否直接决定这一行算不算净开一层、进而决定收尾行找不找得到）。
   已把样本换成真形态（字符串版 + 注释版两条），并**由变异 M3 证明它现在真的会红**。
2. **外移时漏掉了「第三个写者」。** 附 B.3 第 1 条问「被搬走的状态有没有**别的读者**」——
   基线里 `markExited` 挂在**三个**监听器上（`error` / `exit` / `close`），我的 `trackChildExit`
   只搬了两个。**用例全绿、`tsc` 全绿、67 个 MCP 用例全过**，因为它表现为「关不掉」或
   「多等一个宽限期」。实测 `spawn` ENOENT 的事件序是 `error:ENOENT → close:-2`（所以常见路径
   侥幸无恙），但那是**观察到的**行为、不是文档承诺 ⇒ 已补回第三个写者，并保持 1:1 映射。
   这条清单项**当场变现**：机械对拍里 `'exit'` 计数 1→2 是线索，顺着它才读出监听器数量对不上。
