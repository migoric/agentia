# RSI 与「能力库」：agentia × agentia-harness 的优化与联动方案（2026-11-27）

> **定位**：这是一份**跨两仓**的方案，不是单仓 roadmap。`agentia` 是运行时与观测面，
> `agentia-harness` 是评测仪器与自改进闭环；两者依赖单向（harness → agentia），
> 所以凡涉及"谁为谁让路"的判断都按这条单向性做。
>
> **它不是 spec**：不锁定任何公共语义。落定后该进 `docs/spec.md` §10 的条目，
> 各自按当日 slug 另记。
>
> **外部依据**（2026-09 至 11 的三份材料，本方案的取舍都对着它们做）：
> - RRSI（Google Research，`arXiv:2609.24972`）：未正则化的 harness 自我进化在进化集上
>   92.8 / OOD 40.3 / 3.80M tokens；加正则化后 90.5 / 43.6 / 2.42M —— **分数、迁移、成本
>   三个指标同时反向**。手段是"提议端限编辑数 + 选择端 critic/pruner"。
> - ModularRSI（IQuest 等，`arXiv:2609.14857`）：冻结权重只改 harness，Terminal-Bench 2.0
>   从 47.57 → 52.43，且改进**迁移到未见任务、其它领域与其它基础模型**。
> - Super-agent（DeepSeek Harness，2026-10-31）：Router + Worker 双层。真正的增量不是
>   "多 agent"，是**把人的注意力当稀缺资源调度**（Router 只调度不执行、Worker 独立上下文、
>   事件驱动主动干活）。

## 1. 结论先行

两个仓的优化不该平行做，要按**谁挡住谁**排。结论：

1. **agentia 侧没有一条在阻塞 harness** —— 闭环已在跑。被挡住的是**归因粒度**与
   **跨工程迁移**，两者都在 harness。
2. RSI 的天花板不在提案器，在**判据的覆盖面**（只有能被断言的东西才能被进化）与
   **复杂度的正则化**（加得越多、分越高、迁移越差）。
3. 所有联动只允许表现为「agentia 多导出只读派生数据 / harness 多读一列」。
   不许出现「harness 要求 agentia 改 API」—— 单向依赖是两仓最值钱的约束。

> 第二批（§3.1 分期留出 + §3.2 净简化配额）也已在同一晚落地，验证记录见 §7.2。

### 2.1 agentia：run 根属性名单源 + 外发（0.10.16）

**症状**：`tools.menuHash` / `tools.names` / `prompts.versions` 三个 run 根属性此前是
`engine/loop.ts` 里的**裸字面量**（写入侧自用，包内没人按名字读）。一旦出现包外读者
（评测仓判"两份跑分可不可比"），抄字面量的一方在上游改名那天**不报错**，只会读到
`undefined` —— 方向恰好是"误判为可比"，比漏记更贵。这与 `llm.fallback` /
`config.fallbacks` 是同一类，处理方式沿用同一条先例。

**改动**：

| 文件 | 改动 |
| --- | --- |
| `src/core/trace.ts` | 新增 `MENU_HASH_ATTR` / `MENU_NAMES_ATTR` / `PROMPTS_VERSIONS_ATTR`，各带"为什么单源"的头注 |
| `src/engine/loop.ts` | 三处 `setAttribute` 改引常量（值逐字不变） |
| `src/index.ts` | 三个常量进公共导出面（additive） |
| `tests/architecture/tool-event-names.test.ts` | `NEEDLES` 从 4 条扩到 7 条：字面量值断言 + 全 `src` 扫描 + 单源处数断言 |
| `packages/website/src/fragments/api.html` | 两行表格 + 导出手写计数 269 → 272 |

**兼容性**：公共面**只增不改**；trace 里写出的字符串逐字未变 ⇒ 既有消费者与既有 trace
读数不受影响。**版本按 patch 走**。

### 2.2 harness：可比性指纹（读菜单与资产版本）

**症状**：`model-read.ts` 只回答了"换了模型没有"。两份跑分不可比的病因还有两个，
而它们恰好都写在 run 根属性上：**菜单变了**（多一个工具 / 某个 schema 收紧）与
**措辞变了**（@Prompt 资产换版本）。缺这两个读数时，通过率掉 20pt 只能靠回忆归因，
而回忆错的方向是把"换了资产"读成"模型抖动"。

**改动**：

| 文件 | 改动 |
| --- | --- |
| `src/run/menu-read.ts`（新） | `menuFacts(trace)`：**只在 run 根读**（子循环不设根属性，故无需另做过滤）；多个根说同一句话才取值，互相矛盾则缺席 |
| `src/evals/types.ts` | `CaseResult.menuHash?` / `.promptVersions?`；`EvalReport.menuHashes?` / `.promptVersions?`；`summarize` 内 `unionOrUnknown` 聚合 |
| `src/evals/run-one.ts` | 成功路径与"前几轮已跑完但崩了"的路径都带上（后者漏掉会让整批变成"不知道"） |
| `src/cli/render.ts` | 比较视图多两行读数（`菜单` / `版本`）+ 三条注意；**只出声、不否决** |
| `tests/menu-facts.test.ts`（新） | 12 条：读取三档语义 / 聚合三档 / 渲染出声 / "不否决" |

**三档语义（关键，别压平）**：

| 读数 | 含义 | 动作 |
| --- | --- | --- |
| 缺席 | **不知道**（老报告、或有用例没留下根属性） | 警示"无法确认"，不说"不同" |
| `[]` | **确认没有**（裸用例没挂工具、资产没写 `version`） | 视为一致 |
| 多个值 | 这批用例内部就不一致（多轮跑到一半换了菜单） | 警示，不归因到单一次改动 |

**为什么不动 `gate()`**：加一条否决会改变"什么算变好"的对外解释权（`gate` 的判定表在
README 里是对外承诺），而"换菜单 / 换资产版本"本身都是**合法实验**。RRSI 的正则化也不是
否决，是**选择端**的过滤 —— 与"只出声"同构。真要升级成否决，须同时改 README 那张表，
单独一次改动。

1. 先发 `@migor/agentia` **0.10.16**（含三个常量）。

3. harness 发版。

## 3. harness 待做（按性价比排，全部**不动**七条不变量）

### 3.1 分期留出（P0）—— ✅ 已落地（2026-11-27 晚）

**症状**：`holdout` 只验一次是对的（不变量 8），但它只保护**有限轮次**。30 轮 × 每轮 5%
显著性，累积假阳性约 78%（`1 - 0.95^30 = 78.5%`）—— 闭环越转越自信，而每一轮的门都在
"合法地"放过一点噪声。

**落成**：`evals/*.md` 加 `phase`（正整数，只对 `split: holdout` 有意义），每批**只用一次**，
消耗记进 `.workspace/rsi/holdout-uses.jsonl`；批用尽即**拒绝**（`留出集不可用：…全部用过`），
提示补新用例或收工。`src/rsi/holdout-batch.ts` = 选择 + 消耗账，`runCycle` 与
`rsi accept --from` 共用同一个选择器（手写提案不是后门）。

**和原方案的三处偏离（都是有意的）**：

1. **显式 `phase`，不按名取模**。取模在「加一条用例」时会重排批次身份，消耗账按 `phase` 记，
   两者一错位，「这一批用过几次」就再也算不清。
2. **未分期不硬拦，只出声**（`enforced: false` + `priorUses`）。原方案「超 K 轮强制停」对
   已有工程是 breaking change，且症状是「RSI 忽然不干活了」。计划里的口径本来就是
   「缺席 = 不知道，出声」，这里照办：可复用、但复用次数落盘、`rsi status` 打印告警。
3. **基线跟着批次收窄**（`subsetReport`）。原方案没提，但第一批跑起来就撞上：候选只跑一批，
   拿整份留出集当基线，门先报 `case_set_changed`（"仅基线有 h2"）—— 那不是判定标准变了。
   这是"分批"这件事真正的隐藏成本，任何实现都必须解。

**没做**：原方案的「拿现有 journal 回放，统计换批会不会翻案」。仓库里没有 30 轮真实 journal
（`cycles/` 是本地状态、不入库），硬造会得到一条看起来精确其实无意义的数。替代判据更硬：
`tests/holdout-batch.test.ts` 8 条 + 一次真实三轮走查（见 §7.2），证明是**机制**生效而不是
统计推断。这条留给有真实数据的人补。

### 3.2 净简化配额（P0）—— ✅ 已落地（2026-11-27 晚）

**症状**：`docs/rsi.md` 门表第 5 行是"通过率提升 → token 涨多少都放行（只记录）"。
理由（用预算换能力是合理交易）成立，但它是**单向棘轮**：每一轮都可以加一点，没有一轮
被迫删。RRSI 的对照组正是这么长成 3.80M tokens / 更低 OOD 的。

**落成**（`src/rsi/shrink.ts`）：连续 `every`（缺省 5）条采纳的改动没让资产变小，**或**
累计成本增幅超 `maxGrowth`（缺省 50%，相对增幅逐条相加）⇒ 下一轮是简化轮。简化轮里：
提示词写"只许删与合并 + 目标字数"，变胖的提案在**跑评测之前**被挡下，「不变差但更小」算值得
（正文净减少 ≥ 5%）。`--shrink-every` 可临时收窄；`RoundStopReason` 增 `shrink_stalled`。

**和原方案的两处偏离**：

1. **判据是「正文净减少」，不是「`assetFingerprint` 文本总量」**。指纹是哈希，比不出大小；
   要"总量"就得先定义"总量"是什么（跨资产求和？），而 L1 一轮只改一个资产 —— 单资产正文
   长度已经是完整信息，跨资产求和只会引入"改 A 补 B"的套利。
2. **状态不落游标，从 `cycles/*.json` 现算**。原方案写"记进 cycles"，但没说"谁是真相"；
   加一个"当前是不是简化轮"的文件就多一处会与历史不一致的状态。现算的额外收获：`dry-run`
   的采纳**不算数**（资产没动过），这条只有从记录里读才想得起来。

**一个必须写明的边界**：配额只在**有失败样本**的轮次里生效（`runCycle` 没失败就收工）。
这不是漏洞 —— 没有采纳就没有变胖，棘轮那时本来也没转。全绿的工程想瘦身，手动删。

### 3.3 提案空间扩到 frontmatter 白名单（P1，收益最大）

**症状**：`propose.ts` 三条约束（只改正文、不动 frontmatter、不许要新工具）把进化对象
锁死在"怎么说"。而 ModularRSI 证明收益最大的一块是**怎么跑**：上下文怎么管、失败怎么恢复、
什么时候算完成。

**做法**：把控制流里 4 个判据提成**声明式字段**并进白名单 —— `compactWhen`（上下文阈值）、
`retryOn`（哪些错误类重试）、`stopWhen`（收尾判据）、`maxDelegate`（委派层数上限）。
它们仍是文本、仍可 diff、仍可回滚，于是自动进提案空间；不变量一条不破（"frontmatter 不可变"
放宽成"白名单字段可变"，其余字段照旧只读）。

**风险**：这是唯一会**改行为语义**的一项，必须配"白名单外的字段被改 ⇒ 提案直接拒"的守卫，
以及一条"同一提案里既有白名单又有非白名单 ⇒ 整份拒"的用例。

### 3.4 `harness label` + 断言候选（P1）

**症状**：断言只来自 trace 与最终文本（对，且必须坚持）。代价是判据覆盖面 = 进化上限。
现在只有两个来源：线上事故（`harvest`）与已知失败用例。**"门放过了、但人一眼看出是坏的"
这一类没有入口**。

**做法**：`harness label <traceId> --bad --reason "…"` 落一份标注；由它生成**候选断言**
（diff 形式）交人审。硬约束：候选断言只能进 `train`，**绝不自动进 holdout、绝不自动采纳** ——
"补一条断言"正是"改测试让自己通过"的合法外观，必须留人在环。

### 3.5 归因规则版本化（P2，便宜）

**症状**：`journal` 记了失败模式签名，但没记**归因规则的版本**。改一次 `attribute()` 的
分类规则，历史签名就与新签名不可比，而"跨轮记忆"会把旧结论当成新证据读 —— 直接骗提案器。

**做法**：`journal.jsonl` 每条加 `ruleVersion`（`attribute.ts` 里一个常量，改动即 bump）；
读账本时版本不同的条目降级为"仅参考方向"，不进"已试过并否掉"的强约束。

### 3.6 `--from-pack` 跨工程迁移（P2，产品向）

**症状**：每个工程从零进化。而 ModularRSI 的核心结论是改进**可迁移**；你的资产是 markdown +
journal + manifest（依据/假设/预测/风险），恰好是"可迁移知识"的格式。

**做法**：`harness rsi accept --from-pack <pack>`：把 A 工程采纳过的提案（补丁摘要 + manifest
+ 预测）作为 B 工程的**候选**，仍走 B 的完整门（含留出）。产品含义变了 —— 卖的不再是
"一个能自我改进的工具"，而是"一个被门验证过、越用越厚的改进库"。

### 3.7 ledger 两列（P3）

`rsi ledger` 每轮并排打 `passRate` 与 `tokens`。RRSI 那张"30 轮曲线"你自己就能画，
不用等外部论文替你论证复杂度膨胀。

`parentTaskId` 排最后 —— 等真有人拿 agentia 搭 Router 再做，现在做等于为一个不存在的用户设计。

## 6. 否决方案（写下来，免得下次重新论证）

- **agentia 内建 RSI**：判据必须在写权限之外，而框架的写权限就是使用者的代码。
  框架一旦能改自己的评测，就没人能审计它。
- **自我改写 gate**（哪怕叫 meta-evolution）：RRSI 的 critic/pruner 是**选择端**的正则化，
  属于 harness 的调度，不属于被测对象。把门也变成可进化对象 = 把唯一的地基交出去。
- **code mode / REPL 沙箱**：收益在工具编排密集的 coding agent；`@Skill` 已经用代码表达了
  确定性编排。引入 = 沙箱 + 每个 tool 边界鉴权 + 供应链，与"零运行时依赖 / 3MB"对撞。
- **权重层（fine-tune / LoRA）**：两仓的立论是"权重冻结、只改模型之外"。沾了权重，
  评测-回滚-审计这一整套要重写。
- **让 Router 长成第二个 agentia**：Router 的价值是"少做事"，它一开始执行就退回 Team Agent
  的老问题。
